# F.5 — Capability Forge Contract

**The pattern → capability substrate.** Mines successful Initiative Engine executions for repeatable patterns, generates capability templates from them, and registers them via the existing capability registry. **Operator must approve every registration** — no auto-register.

---

## Purpose

Capability Forge answers:
1. **"What patterns have worked?"** — Mine successful initiatives for repeating (kind → target_tool → risk) patterns
2. **"What would a reusable template look like?"** — Generate capability descriptors from patterns
3. **"Should we register this?"** — Operator reviews + approves
4. **"What's been registered?"** — Audit log of all registrations

The **daemon-vs-LLM rule** says: F.5 is **primarily deterministic**. Mining is COUNT(*) queries, templates are JSON shape derivation, registration is gated write.

## Why "operator must approve"

This is the **most critical "long-term" contract** in the system:
- Once a capability is registered, every organ can use it
- Bad registrations = systemic failure
- Capability registry is in-memory but the audit log is persistent
- The audit log is what we use to detect "why did X happen yesterday?"

The chain: `successful initiative → pattern → template → OPERATOR APPROVAL → registered capability`

**F.5 NEVER auto-registers. Operator decides.**

## The Organ Contract

```
MINE         — Read successful initiatives:
                - initiative_proposals WHERE status = 'executed'
                - group by (source, kind, target_tool, required_authority, risk_level)
                - count occurrences
                - compute success_rate, avg_duration, avg_cost
   ↓
TEMPLATE     — For each pattern with ≥ MIN_OCCURRENCES:
                - Generate capability descriptor:
                    capability: "<organ>.<action>"  (e.g. "browser.rate_limit_diagnostic")
                    owner: <organ_name>
                    risk: <risk_level>
                    dependencies: [target_tool]
                    description: "<auto-generated from pattern>"
                - Set status = "pending_review"
   ↓
REGISTER     — Operator reviews template:
                - approve(template_id) → POST to concord backend registerCapability
                - reject(template_id) → status = "rejected"
                - status transition: pending_review → registered | rejected
   ↓
AUDIT        — Every step logged:
                - capability_forge_patterns (mined)
                - capability_forge_templates (generated)
                - capability_forge_registrations (operator actions)
                - Every register/reject has trace_id + timestamp + reason
```

## Tools exposed (5)

| Tool | Purpose | Risk |
|---|---|---|
| `capability_mine` | Mine successful initiatives for patterns | read |
| `capability_list_patterns` | List mined patterns with filters | read |
| `capability_generate_template` | Generate capability descriptor from a pattern | write (DB only, no register) |
| `capability_list_templates` | List pending/registered/rejected templates | read |
| `capability_register` | Operator approves + registers a template | write (capability code: deploy) |

**No `capability_auto_register`.** Operator must explicitly call `capability_register`.

## Mining rules

```python
MIN_OCCURRENCES = 2  # pattern must have at least 2 successful executions
MIN_SUCCESS_RATE = 0.5  # at least 50% success rate

def should_create_template(pattern):
    return (
        pattern.occurrences >= MIN_OCCURRENCES
        and pattern.success_rate >= MIN_SUCCESS_RATE
    )
```

## Template generation (deterministic)

```python
def generate_template(pattern):
    cap_name = f"{pattern.organ}.{pattern.action_snake_case}"
    return {
        "capability": cap_name,
        "owner": pattern.organ,
        "risk": pattern.risk_level,
        "description": (
            f"Auto-generated from {pattern.occurrences}x successful "
            f"{pattern.kind} initiatives targeting {pattern.target_tool}"
        ),
        "dependencies": [pattern.target_tool],
        "implementation": "template",  # marks this as a template, not a real impl
        "mcp_tool_name": pattern.target_tool,
    }
```

## Registration flow

```
capability_register(template_id):
  1. Validate template_id exists in capability_forge_templates
  2. Validate status == "pending_review"
  3. Generate capability descriptor
  4. POST to concord backend: registerCapability(descriptor)
     - Risk: deploy (operator approval required)
     - F0 will gate this
  5. If F0 ALLOWS:
     - Update template: status = "registered", registered_at = now()
     - Update registration log: status = "approved"
  6. If F0 DENIES:
     - Update template: status stays "pending_review"
     - Update registration log: status = "denied", reason_code = f0.reason_code
  7. Notify operator via Telegram (deploy risk)
```

```sql
CREATE TABLE capability_forge_patterns (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    pattern_id TEXT NOT NULL,           -- composite: organ + action + risk
    source TEXT NOT NULL,                -- opportunity | proactive
    kind TEXT NOT NULL,
    target_tool TEXT NOT NULL,
    organ TEXT NOT NULL,                 -- inferred from target_tool prefix
    action TEXT NOT NULL,                -- snake_case action name
    risk_level TEXT NOT NULL,
    occurrences INTEGER NOT NULL,
    success_count INTEGER NOT NULL,
    success_rate REAL NOT NULL,
    first_seen TEXT,
    last_seen TEXT,
    trace_id TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(pattern_id)
);

CREATE TABLE capability_forge_templates (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    template_id TEXT NOT NULL,           -- composite: capability name
    pattern_id TEXT NOT NULL,
    capability TEXT NOT NULL,            -- e.g. "browser.rate_limit_diagnostic"
    owner TEXT NOT NULL,
    risk TEXT NOT NULL,
    description TEXT NOT NULL,
    dependencies_json TEXT,
    implementation TEXT NOT NULL DEFAULT 'template',
    mcp_tool_name TEXT,
    status TEXT NOT NULL DEFAULT 'pending_review',  -- pending_review | registered | rejected
    registered_at TEXT,
    rejection_reason TEXT,
    trace_id TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(template_id)
);

CREATE TABLE capability_forge_registrations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    template_id INTEGER NOT NULL,
    capability TEXT NOT NULL,
    status TEXT NOT NULL,                -- approved | denied | pending
    f0_decision TEXT,
    f0_reason_code TEXT,
    f0_envelope_json TEXT,
    operator_action TEXT NOT NULL,       -- approve | reject
    operator_reason TEXT,
    trace_id TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_capability_forge_patterns_organ ON capability_forge_patterns(organ);
CREATE INDEX idx_capability_forge_templates_status ON capability_forge_templates(status);
```

## Organ inference (target_tool → organ)

```python
def infer_organ(target_tool):
    """Infer organ from target_tool name prefix."""
    if target_tool.startswith("browser_"):
        return "browser-organ"
    if target_tool.startswith("sentinel_"):
        return "sentinel-organ"
    if target_tool.startswith("trace_"):
        return "trace-fabric"
    if target_tool.startswith("incident_"):
        return "incident-engine"
    if target_tool.startswith("research_"):
        return "research-frontier"
    if target_tool.startswith("opportunity_"):
        return "opportunity-engine"
    if target_tool.startswith("proactive_"):
        return "proactive-engine"
    if target_tool.startswith("economic_"):
        return "economic-controller"
    if target_tool.startswith("initiative_"):
        return "initiative-engine"
    return "unknown"
```

## Integration with F0

`capability_register` goes through F0 dispatch with risk: **deploy**.
- Operator explicit action required
- F0 capability gate must ALLOW
- F0 will check: capability name format, owner exists, risk tier valid

## Stop list

- Do NOT create `capability_auto_register` (operator must call explicitly)
- Do NOT bypass operator approval
- Do NOT register patterns with < 2 occurrences
- Do NOT register patterns with < 50% success rate
- Do NOT invoke LLM for template generation
- Do NOT mutate in-memory capability registry directly (always go through F0)

## Daemon-vs-LLM status

Capability Forge is **purely deterministic**:
- Mining: SQL aggregation queries (group by, count, success rate)
- Template generation: dict literal construction
- Registration: HTTP POST to F0
- LLM invocation: zero

If a template needs better description, operator uses Research Frontier.

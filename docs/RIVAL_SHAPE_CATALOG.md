# Rival-Shape Silhouette Catalog

CLAUDE.md's "253-lens frontend" section notes that many lenses mount a
**rival-shape silhouette** — a hand-built chrome component (usually named
`*Shell.tsx`, but not always) that makes a lens visually read as the real
app it replaces within ~200ms, in service of the **per-lens category
leadership** invariant: every lens is judged as an independent product
against its actual category leader (Bloomberg Terminal, Zillow, Epic,
Ableton, …), not "good enough next to its 259 siblings."

There was previously no single index of which components exist, which
lens each belongs to, and which real product each is benchmarked against.
That absence made it easy to (a) not know a silhouette already exists
before scaffolding a new lens, or (b) copy a component that looks live but
has actually been superseded or retired. This document is that index —
**generated by reading each component's own header comment** (and, where
the header stayed silent, the page that mounts it) rather than assumed
from CLAUDE.md's example list, which turned out to be partially stale
(see "Corrections to CLAUDE.md's example list" below).

Reproduction: `grep -rl "shape silhouette\|-shape chrome\|-shape sidebar" concord-frontend/components/` plus a manual read of every `*Shell.tsx` file under `concord-frontend/components/` and the lens pages that import them. 29 distinct components matched the pattern; 23 are actively mounted in a live lens page today, 6 are built (and in most cases still have a pinning test) but are not currently reachable from any lens.

## Corrections to CLAUDE.md's example list

CLAUDE.md's "253-lens frontend" section names 10 examples; verifying each
against the current tree found two that no longer match a real file:

- **code → "VSCodeShell"**: no file by that name exists. The live
  component is `CodeWorkbenchShell.tsx` (an unmounted `CodeEditorShell.tsx`
  also exists — see table above).
- **marketplace → "BandcampGrid"**: no file by that name exists.
  `CreatorGrid.tsx` looks like its successor by description, but it isn't
  mounted either — marketplace's live silhouette is `ShopfrontShell`.

The other eight (music→SessionView, accounting→KPIStrip, atlas→GraphView,
message→InboxShell, crypto→WalletShell, healthcare→EHRShell,
whiteboard→WhiteboardCanvas) partially hold: SessionView, InboxShell,
WalletShell, and WhiteboardCanvas are exactly as described. **KPIStrip is
not accounting's live silhouette** (BooksShell is; KPIStrip is a dead-end
per the table above). **GraphView is not atlas's own silhouette** — it
lives in `components/atlas/` but is mounted by the `literary` lens, not
`atlas` (atlas's own silhouette is `AtlasShell`). **EHRShell is not
healthcare's live silhouette** (EpicShell is; EHRShell is unmounted per
the table above).

## Using this catalog when scaffolding a new lens

1. Check both tables before building a new rival-shape component for a
   lens — a close cousin (same category, different named reference) may
   already exist and just need repointing, rather than a rebuild.
2. If you revive one of the "not currently mounted" components, move its
   row to the top table and update this file in the same PR — don't leave
   a stale "not mounted" note next to a component you just wired live.
3. A new silhouette component should follow the same authoring pattern
   these use: a header comment naming the **specific** real product(s) it
   is benchmarked against (never "make it nice" — name Bloomberg Terminal,
   specifically), consistent with `docs/UI_QUALITY_RUBRIC.md` §0's
   prompting-for-premium-design guidance.

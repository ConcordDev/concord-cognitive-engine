- **Layer 7.5 — env-coupled skills + DBZ stagger + Geo-Mod-light** — `server/lib/embodied/skill-environment.js` couples skills to the environment in three places, all wired through `routes/worlds.js#/api/worlds/:worldId/combat/attack` (lines ~1815–1900) and `/api/worlds/:worldId/nodes/:nodeId/gather` (lines ~1230–1265):
  1. `elementalEnvBoost(element, signals)` — potency multiplier (0.5×–1.6×). Frost magic in cold cells ≥1.5×, weak in heat (≤0.5×); fire on dry sunny day 1.4×, weak in storm (≤0.6×); lightning in storm 1.6×; bio prefers humid + clean; energy follows sunlight. Applied AFTER `_validateDamageCap` so the cap stays a tight bound on raw damage and env amplification can legitimately exceed it. Degrades to 1.0× when `signals.hasData === false` so a world without baseline doesn't penalise players.
  2. `elementalEnvFeedback(element, magnitude)` — array of `{ channel, value, ttlSeconds }` deltas the cast writes back. Fire warms (+0.5°C × m, TTL 600s) and drops air quality; water humidifies (+1.5%); lightning thunders + drops air quality + flashes light; bio/poison drop air quality; physical bumps pressure + noise. Caller calls `recordSignal` with `source: 'skill_cast'`. Magnitude normalises 0.1–2.0 from final damage / 50.
  3. `terrainResourceBoost(element, nodeType, signals)` — the bender table for harvest yield: physical+ore_vein/stone/crystal = 1.5× ("Toph"), water+spring = 1.4× ("Katara"), bio+herb/soil = 1.45×, energy+plant in sunlight (>50k lux) = 1.35×, fire+tree in dry conditions (humidity <40) = 1.2×, ice+spring in freezing conditions = 1.25×. Boost is post-`gatherFromNode` so node depletion is unchanged — the bender effect represents more efficient extraction of the same material. Client passes `element` in the gather body.
  4. `shouldStaggerOnTerrain({ element, magnitude, attackerPos, targetPos, db, worldId })` — DBZ-style: high-magnitude hits (≥30) projected 6m forward from the target through `world_buildings`; if a standing/damaged building is within 8m of the projection, returns `{ buildingId, durationMs, structuralStress, elementContrib }`. Material toughness modulates stress (thatch 1.5×, wood 1.2×, stone 0.8×, steel 0.6×).
  5. `applyStructuralStress(db, _worldId, buildingId, stress)` — Geo-Mod-light: drains `world_buildings.health_pct`, transitions standing → damaged (<0.4) → collapsed (=0). Idempotent on collapsed.
  Tests pin all six functions at `tests/embodied-skill-environment.test.js`.
- **Combat env amplification is post-cap.** `routes/worlds.js#/combat/attack` MUST apply `_validateDamageCap` BEFORE `elementalEnvBoost`, never after. Inverted order would (a) break the bender experience by capping legitimate boosts, (b) let a client-side bug exploit stack with env boost to bypass the cap. Test `multiplier × cap interaction: env boost applied AFTER cap` pins this contract.

- **Layer 9 — embodied dream cycle.** Migration 115 added `dreams` (id, user_id, world_id, dream_dtu_id, fragment_count, signature, composer, composed_at). `server/lib/embodied/dream-engine.js`: `gatherFragments` (pulls last `WINDOW_HOURS` of activity from damage_events ± as attacker/target, pain_signals, player_inventory, world_visits, and creator_id-keyed dtus with `kind != 'dream'`), `composeDeterministic` (stitches fragments into grounded prose + structured DTU shape — never invents events outside the fragment list), `tryComposeForUser` (throttles by `MIN_COMPOSE_INTERVAL_S = 6h`, dedupes by signature hash, single-tx INSERT into both `dtus` and `dreams`), `getRecentDreams`. - **Two dream cycles, distinct.** `server/emergent/dream-cycle.js#runDreamCycle(STATE)` is the system-level 6-phase substrate cycle (replay/consolidate/connect/predict/heal/compose) on the global DTU corpus. `server/emergent/embodied-dream-cycle.js#runEmbodiedDreamCycle({db})` is the player-experience layer (one `kind='dream'` DTU per offline player per ~6h). Different abstraction levels, different inputs, different outputs. Don't merge them.
- **Dream gather excludes prior dreams.** `dream-engine.js#gatherFragments` filters `dtus` by `kind != 'dream'`; otherwise the previously-composed dream DTU becomes a fragment of the next compose, shifting the signature and breaking the duplicate-signature dedupe path. Tests pin this at `tests/embodied-dream.test.js#dedupes duplicate signatures across cooldown boundary`.
- **LLM-enhanced composition is opt-in.** `CONCORD_DREAM_LLM=true` enables routing dream prose through the subconscious brain (port 11435). Default deterministic. Even with LLM enabled, the prompt is constrained to the fragment summary so the brain can't invent events the player didn't experience. On any failure or timeout (8s), the deterministic composer is used.
- **Layer 10 — subconscious forward-sim (anticipation).** Migration 116 added `forward_predictions` (subject_kind ∈ quest|npc|decision|faction|self, subject_id, anticipated prose, confidence 0..1, composer, composed_at, expires_at, realised_at, reality_outcome). `server/lib/embodied/forward-sim.js`: `tryPredictForUser` (throttles by `MIN_PASS_INTERVAL_S = 4h`, skips subjects with active non-realised predictions, generates up to `MAX_PREDICTIONS_PER_PASS = 3` predictions per call), `composeDeterministicPrediction` (per-subject-kind prose with seeded confidence — quests highest, factions lowest), `getActivePredictions`, `realisePrediction` (caller stamps reality_outcome JSON when reality matches), `sweepExpiredPredictions` GC.
